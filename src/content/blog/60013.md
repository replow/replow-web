> 本文写于 2026 年 8 月 6 日。CC Switch 更新较快，请优先查看 Releases 页面中的最新稳定版本，不要只根据版本号大小判断是否稳定。

CC Switch 是一个开源的 AI 编程工具供应商管理器，可以统一管理 Claude Code、Codex、Gemini CLI 等工具的 API 配置。对于 Codex，它既能直接切换原生支持 Responses API 的供应商，也能通过本地路由把 Codex 的 Responses 请求转换成第三方常见的 Chat Completions 请求。

这篇文章从下载和安装开始，完整介绍如何让 CC Switch 接管 Codex，并说明如何验证、排错和恢复官方配置。

## 一、先确认官方下载渠道

CC Switch 的唯一官网是 [ccswitch.io](https://ccswitch.io/)，源码和安装包发布在 [farion1231/cc-switch](https://github.com/farion1231/cc-switch) 仓库。

推荐下载渠道：

- [CC Switch 官方网站](https://ccswitch.io/)
- [GitHub Releases](https://github.com/farion1231/cc-switch/releases)
- [GitHub 源码仓库](https://github.com/farion1231/cc-switch)

不要从要求充值、付费下载或索取账号登录凭据的同名网站获取安装包。CC Switch 本身是开源软件，第三方 API 供应商是否收费则取决于供应商自己的计费规则。

截至 2026 年 8 月 6 日，`v3.19.2` 被标记为 Pre-release。希望优先保证稳定性时，可以选择 `v3.19.1`；以后阅读本文时，应选择 Releases 页面中最新的非预发布版本。

## 二、安装前的准备

CC Switch 官方手册给出的最低环境包括：

- Windows 10 或更高版本，x64
- macOS 12 Monterey 或更高版本，Intel 或 Apple Silicon
- Linux x64 或 ARM64

使用 CC Switch 接管 Codex 前，需要先确保 Codex 可以正常启动。打开终端执行：

```bash
codex --version
```

如果命令不存在，请先参考 [OpenAI Codex CLI 官方页面](https://developers.openai.com/codex/cli/) 安装 Codex。安装后至少启动一次 Codex，让它创建配置目录。

Codex 的主要配置位于：

```text
~/.codex/auth.json
~/.codex/config.toml
```

Windows 中的 `~` 通常对应：

```text
C:\Users\你的用户名
```

因此完整目录通常是：

```text
C:\Users\你的用户名\.codex\
```

在开始切换前，建议手动复制一份 `.codex` 目录。CC Switch 本身也会保存配置和备份，但额外备份能让恢复过程更从容。

## 三、安装 CC Switch

### Windows 安装版

1. 打开 GitHub Releases 页面。
2. 下载 `CC-Switch-v{版本号}-Windows.msi`。
3. 双击 MSI，按照安装向导完成安装。
4. 从开始菜单启动 CC Switch。

如果双击安装包没有反应，可以右键文件，打开“属性”，在“常规”页面检查是否存在“解除锁定”选项。

### Windows 便携版

1. 下载 `CC-Switch-v{版本号}-Windows-Portable.zip`。
2. 解压到固定目录。
3. 运行 `CC-Switch.exe`。

便携版不需要安装，但不要把它长期放在下载目录或临时目录，否则更新、备份和开机启动管理会比较混乱。

### macOS

推荐使用 Homebrew：

```bash
brew install --cask cc-switch
```

更新时执行：

```bash
brew upgrade --cask cc-switch
```

也可以从 Releases 下载 DMG，将 `CC Switch.app` 拖入“应用程序”。官方 macOS 构建已签名并完成公证。

### Debian 和 Ubuntu

根据处理器架构下载对应的 DEB：

```bash
sudo dpkg -i CC-Switch-v{版本号}-Linux-*.deb
sudo apt-get install -f
```

第二条命令只在提示依赖缺失时执行。

### AppImage

```bash
chmod +x CC-Switch-v{版本号}-Linux-*.AppImage
./CC-Switch-v{版本号}-Linux-*.AppImage
```

## 四、理解“直接切换”和“接管路由”的区别

这一步很重要。不是所有 Codex 供应商都需要本地路由。

Codex 新版本主要使用 OpenAI Responses API，而第三方服务可能提供两种协议：

- **Responses 原生协议**：Codex 可以直接连接，通常不需要开启路由接管。
- **Chat Completions 协议**：需要 CC Switch 在本地完成 Responses 与 Chat Completions 之间的格式转换。

最简单的判断方式，是查看 CC Switch 的 Codex 供应商卡片：

- 出现“需要路由”标记：必须开启本地路由和 Codex 接管。
- 没有该标记：通常可以直接启用。
- 出现“不支持路由”：不要让该供应商走本地路由。

不要把第三方的 `/chat/completions` 完整接口地址直接写入 Codex。Codex 发出的是 Responses 请求，协议不一致时常见表现包括 `404`、`400`、模型列表错误或流式响应无法解析。

## 五、在 CC Switch 中添加 Codex 供应商

1. 打开 CC Switch。
2. 切换到顶部的 `Codex` 标签。
3. 点击右上角的 `+`。
4. 优先从预设列表选择你的供应商。
5. 填写 API Key。
6. 检查默认模型和端点。
7. 保存供应商。

使用预设时，CC Switch 会自动填写 Base URL、模型和协议类型，出错概率最低。

如果供应商不在预设列表中，可以选择“自定义”，重点检查：

- 名称：便于自己识别。
- API Key：只保存在可信设备中，不要截图公开。
- Base URL：填写供应商文档给出的服务根地址，不要随意追加 `/chat/completions`。
- 模型：填写供应商实际支持的模型 ID。
- 上游格式：选择 Responses 原生或 Chat Completions。
- 推理能力：只有自动判断不正确时才需要手动调整。

保存后，如果卡片显示“需要路由”，继续下一节。

## 六、启动本地路由并接管 Codex

CC Switch 默认在本机启动 HTTP 路由服务：

```text
http://127.0.0.1:15721
```

推荐保留监听地址 `127.0.0.1`，这样只有当前电脑可以访问。除非明确需要给局域网设备使用，否则不要改成 `0.0.0.0`。

操作步骤：

1. 进入“设置”。
2. 打开“高级”中的“代理服务”或“路由服务”。不同版本的界面名称可能略有差异。
3. 启动路由服务。
4. 在“应用路由”区域找到 Codex。
5. 打开 Codex 路由或 Codex 接管开关。
6. 回到 Codex 供应商列表。
7. 点击目标供应商卡片上的“启用”。

接管成功后，CC Switch 会把 Codex 的实时配置指向本地路由。典型形式类似：

```toml
base_url = http://127.0.0.1:15721/v1
```

真实 API Key 由 CC Switch 保存在供应商配置中，并由本地路由在转发请求时注入。不要为了“看起来正确”而手动覆盖 CC Switch 写入的配置。

请求链路大致如下：

```text
Codex Responses 请求
        -> CC Switch 本地路由
        -> 第三方 Responses 或 Chat Completions API
        -> CC Switch 转换响应
        -> Codex
```

路由模式还可以记录请求、统计 Token、切换供应商和配置故障转移。单纯为了协议转换时，不需要打开所有高级功能。

## 七、保留 Codex 官方登录状态

如果你同时使用 Codex Desktop、官方插件或远程控制能力，可以保留官方登录状态，让第三方供应商只接管模型流量。

推荐顺序：

1. 在 CC Switch 的 Codex 页面先启用 `OpenAI Official`。
2. 启动 Codex，按照官方流程登录一次。
3. 确认 `~/.codex/auth.json` 已生成。
4. 打开“设置 -> 通用 -> Codex 应用增强”。
5. 开启“切换第三方时保留官方登录”。
6. 再切换到第三方供应商。
7. 如果第三方供应商显示“需要路由”，启动路由并开启 Codex 接管。

开启后，Codex 界面仍可能显示官方账号，但实际模型请求以 CC Switch 当前供应商、`config.toml` 和路由日志为准。

不要通过 CC Switch 本地路由访问 `OpenAI Official`。官方供应商应在关闭 Codex 接管后直接使用，避免不必要的账号和合规风险。

## 八、重启并验证 Codex

普通配置切换后，Codex 通常需要重新启动：

1. 结束当前 Codex 会话。
2. 关闭原终端窗口。
3. 重新打开终端。
4. 执行 `codex`。
5. 发出一个简短测试请求。

还可以从以下位置检查：

- Codex 中使用 `/model` 查看模型是否正确。
- CC Switch 中目标供应商是否显示为路由活跃状态。
- 路由面板的请求数量是否增加。
- 请求日志中是否出现 Codex 请求和正确的上游模型。
- `~/.codex/config.toml` 是否指向 `127.0.0.1:15721/v1`。

在路由接管模式下切换供应商通常可以立即生效，但如果修改了模型映射或模型目录，仍建议重启 Codex。

## 九、常见问题

### Codex 返回 404 或找不到 responses

常见原因是供应商只有 Chat Completions 协议，但没有启动路由接管。

检查：

- 供应商卡片是否显示“需要路由”。
- 路由服务是否正在运行。
- Codex 接管开关是否打开。
- `config.toml` 是否指向 `http://127.0.0.1:15721/v1`。
- 自定义 Base URL 是否错误地包含了 `/chat/completions`。

### 切换后没有生效

关闭当前 Codex 和终端，再重新启动。Codex 不一定会热加载 `config.toml` 和模型目录。

### 看不到新模型

保存供应商后重新启动 Codex。CC Switch 会生成模型目录并写入 `model_catalog_json`，正在运行的 Codex 进程不一定立即刷新。

### 端口被占用

先停止 CC Switch 路由服务，再修改监听端口，然后重新启动。不要在服务运行时直接修改端口。

### 无法停止路由服务

先关闭 Codex 接管开关，再停止整个路由服务。只停止服务但仍保留应用接管，会让 Codex 指向一个不存在的本地端点。

### 官方登录被覆盖

切回 `OpenAI Official`，重新启动 Codex 并完成一次官方登录。随后开启“切换第三方时保留官方登录”，再切回第三方供应商。

## 十、关闭接管和恢复官方 Codex

1. 在 CC Switch 中关闭 Codex 路由接管。
2. 停止本地路由服务。
3. 切换到 `OpenAI Official`。
4. 关闭并重新启动 Codex。
5. 必要时重新执行官方登录。

正常关闭接管时，CC Switch 会尝试恢复接管前的配置。遇到异常退出时，可以从 CC Switch 的备份目录或开始前手动保存的 `.codex` 副本恢复。

CC Switch 的默认数据目录是：

```text
~/.cc-switch/
```

其中包含 SQLite 数据库、设置、Skills 和自动备份。`auth.json`、API Key、数据库备份都属于敏感信息，不要上传到公开仓库或发送给陌生人。

## 十一、安全建议

- 只从 `ccswitch.io` 和官方 GitHub 仓库下载。
- API Key 只填写在本机 CC Switch 中。
- 不要公开 `~/.codex/auth.json`。
- 本地路由优先监听 `127.0.0.1`。
- 不要盲目导入来源不明的 `ccswitch://` 配置链接。
- 使用第三方供应商前，先阅读其隐私政策、数据保留和计费规则。
- 官方 OpenAI 登录和第三方 API 计费是两套概念，不要只看 Codex 显示的账号判断流量去向。
- 不需要协议转换时，优先使用 Responses 原生直连，减少一层路由复杂度。
