# SilverCode Nexus AccessKey API 使用文档

> 文档版本：1.0  
> API 基础地址：`https://user.replow.org/api/v1/user`

SilverCode Nexus AccessKey API 允许你通过脚本、自动化程序或服务器调用自己的账号功能。目前支持读取账号资料、投稿文章、修改头像链接和修改显示名称。

## 一、生成 AccessKey

1. 登录 `https://user.replow.org/user/`。
2. 打开个人中心中的“AccessKey”页面。
3. 填写 Key 名称并选择过期时间。
4. 点击“生成 AccessKey”。
5. 立即复制并妥善保存完整 Key。

每个账号最多保留 1 个 AccessKey。完整 Key 只会显示一次，网站数据库只保存不可逆哈希，管理员也无法帮你找回。

如果 Key 遗失、泄露或不再使用，请在个人中心删除。删除后，所有使用该 Key 的程序都会立即失去访问权限。需要重新使用时，再生成一个新的 Key。

## 二、认证方法

所有请求都必须携带以下请求头：

```http
Authorization: Bearer YOUR_ACCESS_KEY
Content-Type: application/json
Accept: application/json
```

请把 `YOUR_ACCESS_KEY` 替换为个人中心生成的完整 Key。

AccessKey 只能访问 `/api/v1/user` 及其子接口。它不能登录网页、不能管理 AccessKey、不能调用管理员接口，也不能绕过文章审核。

## 三、读取当前账号

请求：

```http
GET /api/v1/user
```

curl 示例：

```bash
curl https://user.replow.org/api/v1/user \
  -H "Authorization: Bearer YOUR_ACCESS_KEY" \
  -H "Accept: application/json"
```

成功响应：

```json
{
  "ok": true,
  "data": {
    "uid": 10000,
    "username": "replow",
    "email": "user@example.com",
    "name": "Replow",
    "avatar_url": "https://cdn.example.com/avatar.webp",
    "bio": "",
    "website_url": "https://www.replow.org",
    "role": "user",
    "status": "active",
    "created_at": "2026-08-14 00:00:00"
  }
}
```

## 四、通过 API 投稿文章

请求：

```http
POST /api/v1/user/post
```

必填参数：

- `title`：文章标题，最多 200 个字符。
- `body_markdown`：Markdown 正文，不能为空，最大 2 MiB。

可选参数：

- `excerpt`：文章摘要，最多 500 个字符。
- `slug`：文章别名；留空时系统会根据标题自动生成。
- `cover_url`：封面图片的完整 HTTP 或 HTTPS 地址。
- `icon_url`：作者图标的完整 HTTP 或 HTTPS 地址。

curl 示例：

```bash
curl -X POST https://user.replow.org/api/v1/user/post \
  -H "Authorization: Bearer YOUR_ACCESS_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "通过 API 投稿的文章",
    "excerpt": "这是一篇自动化投稿示例。",
    "body_markdown": "# Hello SilverCode Nexus\n\n正文支持 **Markdown**。",
    "cover_url": "https://cdn.example.com/cover.webp"
  }'
```

成功时返回 HTTP `201`：

```json
{
  "ok": true,
  "data": {
    "id": 60020,
    "title": "通过 API 投稿的文章",
    "slug": "通过-api-投稿的文章",
    "status": "pending",
    "review_required": true,
    "created_at": "2026-08-14 12:00:00",
    "updated_at": "2026-08-14 12:00:00"
  }
}
```

API 投稿固定进入 `pending` 待审核状态。即使账号是管理员，AccessKey 也不会直接发布文章。请在个人中心查看投稿状态。

## 五、修改头像

请求：

```http
POST /api/v1/user/avatar
```

参数：

- `avatar_url`：必填，头像的完整 HTTP 或 HTTPS 地址，最长 2048 字节。

示例：

```bash
curl -X POST https://user.replow.org/api/v1/user/avatar \
  -H "Authorization: Bearer YOUR_ACCESS_KEY" \
  -H "Content-Type: application/json" \
  -d '{"avatar_url":"https://cdn.example.com/avatar.webp"}'
```

此接口只保存图片链接，不接收图片二进制文件。头像链接应当可以被公网通过 HTTPS 正常访问。

## 六、修改显示名称

请求：

```http
POST /api/v1/user/name
```

参数：

- `name`：必填，新的显示名称，最多 80 个字符。

示例：

```bash
curl -X POST https://user.replow.org/api/v1/user/name \
  -H "Authorization: Bearer YOUR_ACCESS_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name":"New Name"}'
```

修改成功后，接口会返回更新后的账号资料。主站个人资料页缓存也会自动刷新。

## 七、Python 示例

以下示例使用 `requests`：

```python
import requests

ACCESS_KEY = "YOUR_ACCESS_KEY"
BASE_URL = "https://user.replow.org/api/v1/user"

headers = {
    "Authorization": f"Bearer {ACCESS_KEY}",
    "Accept": "application/json",
    "Content-Type": "application/json",
}

response = requests.get(BASE_URL, headers=headers, timeout=20)
response.raise_for_status()
print(response.json())

article = requests.post(
    f"{BASE_URL}/post",
    headers=headers,
    json={
        "title": "Python API 投稿",
        "body_markdown": "# Python\n\n这篇文章来自 API。",
        "excerpt": "Python 投稿示例",
    },
    timeout=30,
)
article.raise_for_status()
print(article.json())
```

不要把真实 AccessKey 直接写进公开仓库。建议通过环境变量读取：

```python
import os

ACCESS_KEY = os.environ["SILVERCODE_NEXUS_ACCESS_KEY"]
```

## 八、Node.js 示例

```javascript
const accessKey = process.env.SILVERCODE_NEXUS_ACCESS_KEY;
const baseUrl = 'https://user.replow.org/api/v1/user';

const response = await fetch(`${baseUrl}/name`, {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${accessKey}`,
    Accept: 'application/json',
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({ name: 'New Name' }),
});

const payload = await response.json();
if (!response.ok || payload.ok === false) {
  throw new Error(payload.message || payload.error || `HTTP ${response.status}`);
}

console.log(payload.data);
```

由于浏览器跨域限制，建议在服务器、命令行、快捷指令或可信任的本地程序中调用，不要把 AccessKey 放进公开网页的 JavaScript。

## 九、频率限制

- 每个 AccessKey 每分钟最多请求 120 次。
- 每个来源 IP 每分钟最多请求 300 次。
- 每个账号每小时最多通过 API 投稿 30 篇文章。

超过限制时返回 HTTP `429`。客户端应当停止连续重试，并在稍后重新请求。

## 十、常见错误

### 401 access_key_required

请求没有携带 `Authorization: Bearer ...`。

### 401 authentication_failed

Key 格式错误、不存在、已过期或已被删除。请检查 Key，必要时在个人中心重新生成。

### 403 access_key_scope_forbidden

AccessKey 被用于 `/api/v1/user*` 以外的接口。请改用本文列出的接口。

### 403 account_banned

账号被封禁，AccessKey 会同时停止工作。

### 401 account_disabled

账号已被管理员停用，AccessKey 会同时停止工作。

### 405 method_not_allowed

请求方法不正确。读取资料使用 GET，其他三个接口使用 POST。

### 422 validation_failed

参数缺失、超过长度限制或 URL 格式无效。错误信息位于响应的 `message` 字段。

### 429 rate_limited

请求过于频繁。请降低调用速度，不要无间隔重试。

### 返回 HTML 而不是 JSON

这通常表示请求被 CDN 或安全验证页面拦截。客户端不要把 HTML 当作 API JSON 解析，可以稍后重试或联系网站管理员。

## 十一、安全建议

- 不要通过聊天记录、截图、前端源代码或公开仓库发送完整 Key。
- 不要在 URL 查询参数中传输 Key，只能放在 Authorization 请求头中。
- 为自动化程序设置合适的过期时间。
- 程序日志中应当隐藏 Authorization 请求头。
- 发现泄露时立即在个人中心删除 Key。
- 不要禁用 HTTPS 证书校验。

AccessKey 的权限是固定的，不支持扩展管理员权限。游戏规则很简单：保管好 Key，脚本就能稳定工作；把 Key 扔进公开仓库，那就是主动给账号开后门了。
