# SilverCode Nexus AccessKey API：AI 接入规范

> Audience: AI agents, code generators, automation tools, and tool-calling runtimes.  
> Contract ID: `silvercode-nexus-user-accesskey-api`  
> Contract version: `1.0`  
> Base URL: `https://user.replow.org/api/v1/user`

## 1. Normative rules

The keywords MUST, MUST NOT, SHOULD, and MAY are normative.

1. The client MUST authenticate with `Authorization: Bearer <access_key>`.
2. The client MUST NOT send the AccessKey in a URL, query parameter, JSON body, log, generated source file, or user-visible output.
3. The client MUST send and accept JSON for POST operations.
4. The client MUST treat the AccessKey as opaque. Do not parse, shorten, transform, or regenerate it.
5. The AccessKey MAY call only `/api/v1/user` and the three documented child endpoints.
6. The client MUST NOT attempt administrator, token-management, media-upload, comment, or undocumented endpoints with this Key.
7. Article submission always creates a `pending` article. The client MUST NOT claim that the article is published.
8. Avatar updates accept a URL only. The client MUST NOT send base64, multipart data, or image bytes.
9. If the response content type is not JSON, the client MUST classify it as an edge/CDN challenge and MUST NOT parse it as an API result.
10. On HTTP `401` or `403`, the client MUST stop automatic retries and ask the user to verify the AccessKey or account state.
11. On HTTP `429`, the client SHOULD use bounded exponential backoff and MUST NOT retry in a tight loop.
12. The client MUST set a finite network timeout.

## 2. Operation selection

- To read the authenticated account, call `getCurrentUser`.
- To submit a new Markdown article for review, call `createArticleSubmission`.
- To replace the account avatar URL, call `updateAvatarUrl`.
- To replace the account display name, call `updateDisplayName`.
- If the user requests any other account action, explain that the AccessKey API does not support it. Do not invent an endpoint.

## 4. Error taxonomy

- `access_key_required`, HTTP 401: Authorization header is missing.
- `authentication_failed`, HTTP 401: Key is malformed, unknown, expired, or deleted.
- `access_key_scope_forbidden`, HTTP 403: Key was used outside `/api/v1/user*`.
- `account_banned`, HTTP 403: The owning account is banned.
- `account_disabled`, HTTP 401: The account is disabled.
- `method_not_allowed`, HTTP 405: Wrong HTTP method.
- `validation_failed`, HTTP 422: Request body is invalid; inspect `message`.
- `rate_limited`, HTTP 429: Rate limit exceeded.
- `database_error`, HTTP 500: Server-side database failure.

The client MUST use both HTTP status and JSON `ok`. A response is successful only when the HTTP status is 2xx and `ok` is `true`.

## 5. Rate limits

- AccessKey: 120 requests per 60 seconds.
- Source IP: 300 requests per 60 seconds.
- Article submissions: 30 per account per 3600 seconds.

Recommended retry policy for transient `429` or `5xx` responses:

1. Retry at most 3 times.
2. Wait approximately 2, 4, and 8 seconds, with random jitter.
3. Do not retry validation, authentication, authorization, or method errors.
4. Do not automatically repeat article submission after an uncertain network timeout unless the user accepts possible duplicate drafts.

## 6. Credential handling requirements

- Read the Key from a secret manager or environment variable such as `SILVERCODE_NEXUS_ACCESS_KEY`.
- Redact the entire Authorization header in logs and traces.
- Never include the Key in prompts sent to unrelated models or services.
- Never echo the Key in assistant messages.
- Never store the Key in browser localStorage, public JavaScript, generated Markdown, or a Git repository.
- If exposure is suspected, instruct the user to delete the Key in the SilverCode Nexus personal center and generate a replacement.
